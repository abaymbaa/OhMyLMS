# Shared skills, general roadmaps and syllabus comparison

Open **Content Hub → Curriculum → Compare syllabuses and map shared skills**. The direct admin route is `#/content-hub/curriculum/compare`.

A shared skill is a reusable, assessable ability with a stable taxonomy ID and UUID. Its library subject and topic are organizational labels; it may appear in roadmaps for different subjects, grades, levels, national curricula and exams. Roadmaps reference the same IDs in learning order. They do not copy skills, lessons, quizzes, content or historical evidence.

## Workflow

1. Select any existing syllabuses or roadmaps, adding up to ten source columns. Each has independent search, topic, category/tier and mapping filters, source ordering and pages of 30 objectives. Version, grade and curriculum context remain visible. Switching columns retains pending mapping selections.
2. Choose a shared skill or create one with an assessable name, scope and topic. Inspect all affected objectives before renaming or editing its scope. Identity and existing links remain intact. Shared skill edits and mapping proposals survive admin navigation in session storage; explicit saves are still required.
3. Select source objectives, review the relationship and differences, and save. Equivalent means the evidence is suitable for pooling for the entire shared ability. Related means overlapping or narrower/broader requirements that remain reference only. Matching names or row positions establish no relationship. Leave uncertain requirements unmapped.
4. Connect lessons, quizzes, assignments, courses or extension resources in **Shared content**. Equivalent mappings resolve these shared owners; no resource is cloned or automatically enrolled. Quiz connections do not rewrite question-to-skill assessments. Use the normal question bank to assign assessed skills to quiz questions.
5. In **Save shared roadmap**, add shared skills in learning order. **New curriculum name** defaults to **Roadmap** and can be changed for each roadmap. Set an optional grade/level, then click **Save as new curriculum**. The draft is inserted above the existing top-level curriculums; the success message links to the curriculum list and the syllabus workspace. The same skill IDs retain their saved syllabus mappings and connected content. Open the existing syllabus workspace to rearrange it, add sections or resources, set prerequisites through the existing skill library, and publish through the existing course validation workflow. Shared roadmap steps use their own content and evidence directly and cannot be mapped onward to another shared skill. Unsaved mapping proposals still require **Save proposed mappings** separately.
6. Enter a subject or study-plan label and explicitly select its syllabuses/roadmaps for learner profiles. Only published syllabus courses appear on learner dashboards. Different labels can use overlapping source sets. The administrator audit accepts a student account ID; students can only read their own progress.

Mapping coverage, direct mastery and pooled shared mastery remain separate. Related mappings contribute neither pooled evidence nor automatic resource inheritance. Combined calculations deduplicate graded answers and never write completion or student skill state. Unassessed skills are not failed mastery. An audit reports unassessed/developing objectives and unmapped/related-only relationships, rather than inventing a readiness percentage or exam score.

## REST and MCP

The additive administrator API lives under `/ohmylms/v1/syllabus-comparison`: `syllabuses`, `objectives/{id}`, `shared-skills`, `shared-skills/{id}`, `shared-skills/save`, `shared-skills/{id}/content`, `mapping`, `mapping/remove`, `roadmaps`, `configuration`, and `audit/{student_id}`. `/me/subject-skills` and `/syllabus-comparison/audit` return only the authenticated account's plans. WordPress REST cookie authentication requires its standard nonce. MCP bearer authentication retains the issuing administrator's capability checks and dispatches through the same REST callbacks.

The MCP add-on adds thirteen tools: `list_syllabuses`, `list_syllabus_objectives`, `list_shared_skills`, `get_shared_skill`, `save_shared_skill`, `save_skill_mapping`, `remove_skill_mapping`, `configure_subject_syllabuses`, `list_shared_skill_content`, `connect_shared_skill_content`, `create_shared_skill_roadmap`, `audit_my_study_plans`, and `audit_student_study_plans`. Native Abilities schemas reject unknown arguments. Tools have accurate read/write, destructive and idempotent annotations. The original nine content-read tools retain their names and behavior.

Shared-skill edits require `expected_revision`. Mapping creation requires an empty revision; edits/removal require the current revision from an objective page. Revisions cover content rather than second-resolution timestamps. Stale edits return HTTP 409. Mapping batches save one pair at a time and retain failed/unsaved selections; successful pairs remain saved. Reload proposal revisions and review before retrying a conflict.

Trusted extensions may add content types through `ohmylms_shared_skill_content_types`, a map of resource kind to registered post type. Content writes require edit permission on the specified post and append/remove only this skill's term relationship. Published learner resource links contain titles and URLs, never draft content or quiz answers; destination access rules remain in force. Resource lists are bounded to 20 per kind/page.

## Initial mathematics sources

The existing local data was inspected: syllabus **5**, `0580 IGCSE`, has 125 objectives, and syllabus **8**, `Digital SAT Math`, has 93. Neither stored a syllabus version at inspection; no mappings existed. These imported texts and codes are preserved. Cambridge 0580 **2028–2030** is the user's selected target, not an automatic certification that older imported descriptions already match it. The comparison visibly flags missing versions. Review/revise the syllabus before assigning its version or publishing a study plan; automatic matching and unreviewed syllabus migration are not implemented.

Official references: [Cambridge 0580 2028–2030, version 2](https://www.cambridgeinternational.org/Images/745681-2028-2030-syllabus.pdf), [Cambridge syllabus update](https://www.cambridgeinternational.org/Images/763300-2028-2030-syllabus-update.pdf), and [College Board Math content](https://satsuite.collegeboard.org/sat/whats-on-the-test/math/types). Digital SAT's imported fine-grained codes are local codes; they are not represented as official College Board objective identifiers. Mongolia or other curricula can be added through the existing syllabus import workflow.

## Compatibility and limits

No existing public route, hook, assessment field, question extension or taxonomy identity was renamed. Existing mapping callers may omit the new expected revision; the new comparison and MCP flows always supply it. New class files retain namespace-matching case for the repository's existing PSR-4 Composer mapping; only the filename sniff is narrowly excepted at the opening line. All other coding checks remain active. MySQL advisory lock calls are necessarily uncached; bounded taxonomy/meta queries still receive performance warnings from WPCS.

Structural splitting/merging, automatic mapping, automatic exam-credit transfer, readiness scores and personalized per-student plan authoring remain outside this release. Profile labels currently define administrator-selected source sets; audits are read-only. Session drafts last for the browser session. Publishing remains an explicit syllabus/course action; configuring a profile does not publish or enroll it.

## Validation

The dedicated integration test uses an isolated WordPress database and exercises multi-source mappings, paging, conflict rejection, stable renames, generic library groupings, resource reuse, ordered cross-subject roadmaps, published-only learner visibility, audits and MCP REST dispatch. The browser test covers three sources, shared-skill creation/mapping/rename, lesson connection, roadmap creation and reopening. Run `tests/php/comparison-integration.php` with `OHMYLMS_TEST_CREDENTIALS`, `node --test tests/js/comparison.test.mjs`, and `tests/browser/comparison.spec.cjs` with the isolated browser configuration.

Validation on 2026-10-12: 47 isolated integration checks, 65 focused JavaScript tests, the browser workflow including invalid-nonce rejection, and curriculum (33), syllabus (56), syllabus settings (19), MCP lifecycle and assessment (186) PHP unit checks passed. Changed PHP files passed syntax checks. New authored comparison modules passed WordPress ESLint, Prettier and scoped CSS checks. New PHP classes had zero WPCS errors and 12 warnings: bounded taxonomy/meta queries and uncached MySQL advisory locks. Production webpack compilation passed with the existing math-runtime/compute-engine size warnings. The standard asset sync hit a Windows mapped-file error while copying existing chunk files; the newly built curriculum chunk and SDK entry/manifest were copied successfully and the shipped browser workflow passed.

The broader working-tree JavaScript run reported 376 tests: 372 passed, three failed, one skipped. Remaining failures are quiz quick-prompt editing, quiz autosave and recovered-asset AST parity. The full-repository standards scan reported 13,945 PHP errors/2,839 warnings, 7,213 JavaScript errors/27 warnings and 1,643 CSS violations. These counts include existing plugin code and concurrent working-tree changes; they are not a claim of a clean repository. No blanket baseline or rule disabling was introduced to conceal them.
